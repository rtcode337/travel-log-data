# gotouchi_gourmet(ご当地グルメ)

- ご当地グルメ・郷土料理 **924件**(47都道府県)。スポットは料理そのものではなく、**その料理を食べに行く土地**
- 出典: Wikipedia(ja)の食のカテゴリの記事。**座標は全件OpenStreetMap**(市区町村の地点)
- ライセンス: **CC BY-SA 4.0**(説明文)+ **ODbL**(座標)。再配布時は出典表示が必要(→[ライセンス](#ライセンス))
- **全924行の根拠を`evidence.csv`に紐づけてある**(どの一文をどう読んで土地を決めたか)

| ファイル | 内容 |
|---|---|
| `spots.csv` | スポットデータ(924件) |
| `evidence.csv` | 行の根拠(`key,article,place_kind,pref,muni,origin_*,local_*,coord,pageviews_month`)。**発祥地とご当地の両方**を持ち、`place_kind`がどちらを座標に採ったかを示す |
| `settings.json` | スポット種別の設定(ランクの有効化・シリーズ11種・カテゴリ5種) |
| `excluded_candidates/not_dishes.md` | 収録しなかった候補と理由(82件) |
| `excluded_candidates/exclude.txt` | travel-log側から削除するスポットの`key`一覧(追記式) |

`buratamori`・`suiyou_dodesho_*`が「LLMの記憶」由来で未検証のまま止まっているのに対し、
**この種別はLLMの記憶を一切使っていない**。土地はWikipedia(ja)の記事本文から機械的な規則で
取り出しており、根拠の一文を`evidence.csv`に残してあるので突き合わせれば検証できる。

## スポットの単位 —— 「料理」ではなく「食べに行く土地」

1つの料理が1つのスポットになり、置く場所は**その料理のご当地**(記事がご当地を書いていなければ発祥地)。
[restaurant](../restaurant/README.md)が「その店に行く」ための点なのに対し、こちらは
「この料理はここで食べる」を地図の上に並べるためのもので、**行き先としての実在性は持たない**
(座標は市区町村の地点であって店の場所ではない)。

**同じ土地の料理は座標が重なる**(名古屋市にひつまぶし・天むす・鬼まんじゅう・ぴよりんが
集中する等)。ずらしていないのは、ずらすとその土地の座標でなくなるため —— 地図上では
ピンが重なり、拡大するか一覧側で読むことになる。

**`日本の郷土料理`と`ご当地グルメ`だけでは足りない。** ご当地ラーメン・ご当地カレー・
ご当地焼きそば・ご当地バーガーはそれぞれ別のカテゴリ体系になっていて、喜多方ラーメン・
佐野ラーメン・富山ブラック・金沢カレー・武蔵野うどんといった**名前が通っているものが
まるごと落ちていた**。

列挙はカテゴリでの絞り込みで行う。**本文の全文検索で`Category:`行を探してはいけない** ——
ソートキー付きの記事(wikitextで`[[Category:日本の郷土料理|きりたんぽ]]`と書かれたもの)は
本文側からカテゴリ名が落ちるため取りこぼす。

### 土地の決め方(3段)

**1. 都道府県を決める。** カテゴリ(`○○県の食文化`・`○○県の麺料理`など)を最優先の
手がかりにし、無ければ冒頭文に出てくる都道府県を採る。**本文だけを見てはいけない** ——
「類似の菓子は福岡県にもある」「隣接する徳島県では…」のような文を掴んで、
いきなり団子が福岡県に、鰹のタタキが徳島県になる(実際にそうなった)。

**2. 地名を「発祥を述べている側」と「ご当地を述べている側」に振り分ける。**
文単位では分けられない —— ボルガライスの冒頭文のように、両方が同じ文にあるため:

> ボルガライスは、**東京都台東区浅草発祥**で、**福井県越前市**（旧武生市域）**を中心に販売されている**洋風カツ丼で、主に越前市のご当地グルメとなったものである。

そこで**地名の直後に来る語**で決める(日本語は「〜発祥」「〜のご当地グルメ」と後ろに続く)。
見るのは次の地名までで、そこで打ち切らないと隣の地名に付く語を拾う。

**3. ご当地を優先して座標にする。** 食べに行く場所が地図に出るようにするため。
記事がご当地を書いていなければ発祥地を使う。

| `place_kind` | 件数 |
|---|---|
| 発祥地 | 470 |
| ご当地 | 391 |
| 節から起こした | 63 |

**ご当地として採るのは冒頭の定義文にあるものだけ**(発祥地がまったく取れていない記事は
本文も見る)。本文まで許すと「両地域のご当地グルメである冷やしラーメンを食べ比べる
イベントが…」のような一文で座標が別の県へ飛ぶ。加えて、その都道府県が**記事のカテゴリか
発祥地の県と噛み合うとき**だけ採る。

### 市区町村まで割るか、都道府県どまりにするか

| 根拠 | 件数 | 何を見ているか |
|---|---|---|
| 冒頭の定義文 | 412 | 記事の書き出しが料理名と市区町村1つだけを結びつけている(「稲庭うどんは、秋田県湯沢市稲庭町が発祥の…」) |
| 発祥・ご当地を述べる文 | 141 | その語の近く(前後26〜28字)に市区町村がある |
| 都道府県のみ | 303 | 上のどちらにも当たらなかった。**市区町村までは特定していない** |

**当てずっぽうで市に置くくらいなら都道府県どまりにする**、が方針。ゆるい規則で拾うと
市区町村の特定率は伸びるが、お好み焼きが神戸市、ほうとうが小鹿野町(埼玉県)になった。
**間違った土地は、無いより悪い**(地図の上では正しいものと見分けが付かない)。

都道府県どまりの303件は**県庁所在地の座標**に置き、`categories`を`都道府県まで`にして、
`description`の末尾に「市区町村までは特定していないため、座標は県庁所在地に置いている」と書く。

- **収録しない選択もあったが、採らなかった** —— 芋煮・きりたんぽ・讃岐うどんのような
  「県全体の郷土料理」がまるごと落ちる。県の代表点であることを明示できるなら、
  出したほうが地図として役に立つ
- **`categories`で絞り込める**ので、市区町村まで割れている621件だけを見ることもできる
- 県庁所在地を代表点にしているのは、県の重心が山中や海上に落ちることがあるため。
  **「県庁所在地がその料理の土地」という意味ではない**

### 発祥地とご当地が違う料理

記事が「発祥はここ、ご当地はここ」と**分けて書いている**ものには`categories`に
`発祥地と別`を付け、`description`に両方を書く。

| 料理 | 座標(ご当地) | 発祥地 |
|---|---|---|
| ボルガライス | 福井県越前市 | 東京都台東区(浅草) |
| 天むす | 愛知県名古屋市 | 三重県津市 |

**この2件は手で確かめて印を付けている。** 機械的に見分けようとすると、
がね・うすやき・寒漬け・みとり饅頭のような**2つの土地にまたがる料理**
(「がねは、鹿児島県、宮崎県都城市の郷土料理」)まで拾ってしまい、印が意味を失う。
冒頭文の中で発祥地とご当地が別々の地名に付いている記事は、実際にはボルガライスだけだった。
`evidence.csv`には全924行について`origin_*`と`local_*`の両方が入っているので、
見落としを洗い直すことはできる。

### 独立記事を持たないご当地版(`節から起こした`)

Wikipedia(ja) には**独立記事を持たず、親記事の一節にしかない**ご当地版が多くある。
ソースカツ丼がその典型で、記事は「カツ丼」の中の一節。そういうものも拾って**63件**足してある。

手がかりは2つで、どちらも`evidence.csv`の`origin_basis`に記録している。

| 手がかり | 件数 | 何を見ているか |
|---|---|---|
| 節の見出し | 36 | 節の見出しが料理名で、その節の本文に地名がある(「ソースカツ丼」→山梨県甲府市) |
| 本文の鉤括弧 | 27 | 鉤括弧でくくった名前のすぐ前(20字以内)に地名がある(「岡山県岡山市のものが『デミカツ丼』の名前で」) |

- **記事1本ぶんの裏付けが無いので、確度は本体の861件より落ちる。**
  そのため`categories`に**`節から起こした`**を付けてあり、絞り込みチップで外せる
- **`rank`は一律E(最小)。** その名前でのページビューが存在しないため、他の行と同じ
  尺度に乗らない。**ランクを空にはしていない** —— 空欄はBと同じ大きさで描かれるので、
  確度の低い行がかえって目立つ
- **`key`は`<親記事>#<名前>`**(`カツ丼#ソースカツ丼`)。名前だけでは親記事に辿れない
- **既に独立記事があるものは足さない。** 候補の名前をWikipedia(ja)のタイトルと突き合わせ、
  記事があるものは落としている(本体の行と二重になるため)
- **`description`は根拠の一文そのもの。** 記事冒頭の要約が無いので、拾った文をそのまま出す
- 拾う範囲を広げすぎない歯止めが2つある —— 名前は**料理名の語尾**(丼・そば・カレー…)を
  持つものだけ、地名は**名前の直前20字以内**にあるものだけ。40字まで許すと
  「島根県の『うずめめし』、東京都深川の『深川めし』、埼玉県小川町の『忠七めし』、
  大阪府難波地方の『かやくめし』」のような**列挙の文**で、隣の料理の地名が付く

### 座標

OpenStreetMapの`place=city` / `place=town` / `place=village`のノード(市区町村の地点)。
Wikipedia(ja)の料理の記事は座標を持たないので、記事側からは起こせない
(ライセンス上の帰結は下記参照)。同名の市区町村が複数の都道府県にあるとき
(中央区・府中市など)は、**都道府県が添えられている場合だけ**採る。

### 説明文・読み・ランク・シリーズ

- `description`は記事冒頭の要約(120字程度)に、末尾の丸かっこで土地を添えたもの(節から起こした行は根拠の一文そのもの)
- `name`は記事名から曖昧さ回避のかっこを外したもの(`ジンギスカン (料理)`→`ジンギスカン`)。
  外すと他の行と衝突する場合だけ記事名のまま(`おつぼ (福井県)`)。`key`は常に記事名
- `name_kana`は冒頭文の読み仮名(400件。持たない記事は空欄)
- `rank`はWikipediaの**月次ページビュー数**(bot除外)。[restaurant](../restaurant/README.md)と
  同じ絶対値のしきい値で区切ってある(母集団が小さくパーセンタイルが安定しないため)

| ランク | 月次ページビュー | 件数 |
|---|---|---|
| A | 10,000以上 | 2 |
| B | 3,000〜9,999 | 31 |
| C | 1,000〜2,999 | 92 |
| D | 300〜999 | 178 |
| E | 300未満 | 621 |

`series`は料理の種類で、Wikipediaのカテゴリ(`日本の魚介料理`など)から決め、
カテゴリで決まらないものは記事名の語尾で補う(「冷や汁」は`日本の米料理`カテゴリを持つので、
カテゴリだけ見ると丼になる)。

| シリーズ | 件数 | | シリーズ | 件数 |
|---|---|---|---|---|
| 麺類 | 299 | | 魚介料理 | 57 |
| 丼・ごはん | 194 | | 菓子・パン | 52 |
| 汁物・鍋 | 70 | | 肉料理 | 40 |
| 野菜・漬物 | 69 | | 寿司 | 39 |
| その他 | 67 | | 粉もの | 34 |
| | | | 飲み物 | 3 |

**ピンの中身は絵ではなく漢字1字**(麺・丼・鮨・粉・汁・肉・魚・菜・菓・飲・他)にしてある。
料理のアイコンは[restaurant](../restaurant/README.md)が既に持っているので、絵にすると
**同じ地図に両方を出したときに見分けが付かなくなる**(ラーメン店のピンと「麺類」のピンが同じ絵になる)。

### 収録しなかったもの

料理そのものではない記事(一覧・概念・大会・団体・番組・店・企業・**即席麺の商品**・
**酒の銘柄**)と、土地を1点に絞れない記事の**82件**。内訳は`excluded_candidates/not_dishes.md`。

飲食店の記事(`らーめん潤`・`カレーの市民アルバ`など)は[restaurant](../restaurant/README.md)の
担当なのでここには入れない。

## 既知の限界

- **節から起こした63件は確度が落ちる。** 記事1本ぶんの裏付けが無く、根拠は1文だけ。
  `categories`の`節から起こした`で外せる
- **土地は記事の記述に従っている。** 諸説ある料理では記事が採った説がそのまま座標になる。
  根拠の一文は`evidence.csv`で読める
- **発祥店までは割っていない。** インフォボックスに`発案店`を持つ記事はごく少数で規則にできない。
  市区町村までが上限
- **料理名に地名を含むものは強い**(富士宮やきそば・喜多方ラーメン・佐世保バーガー)一方、
  **全国に広まった料理ほど弱い**(お好み焼き・たこ焼き・ちらし寿司)。後者は
  都道府県どまりになるか、土地が書かれておらず収録から落ちている
