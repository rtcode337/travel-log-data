# buratamori(ブラタモリ)

- NHK「ブラタモリ」の訪問地 **406件** / ルート **3本**
- 出典: jawikiの番組記事「放送日程」節(訪問地)+ 一般知識(立ち寄りスポット名・説明文)。座標のみosm_japanで裏取り
- **試験データ。具体的なスポット名・説明文・各回との対応関係は未検証(要確認)**

| ファイル | 内容 |
|---|---|
| `spots.csv` | スポットデータ(406件) |
| `routes.csv` | 巡回順が裏取りできる3ルート |
| `settings.json` | スポット種別の設定(全340回のシリーズ定義) |
| `excluded_candidates/exclude.txt` | travel-log側から削除するスポットの`key`一覧(追記式) |

## spots.csv

レギュラー版全5シリーズ(第1シリーズ2009年〜第5シリーズ放送中)について、放送回ごとの
訪問地(都道府県・市区町村)はjawikiの番組公式記事「放送日程」節を参照した上で、具体的な
立ち寄りスポット名・そのスポットの回内での役割の説明文は一般知識から作成した試験データ。
座標のみosm_japanで裏取り済み。アンコール放送・完全版・過去回の再構成スペシャルなど
新しいロケ地情報が無い回は対象外。

`series`列は`description`冒頭と同じ`【#9 品川】`形式(放送回番号+タイトル。スペシャルは
`【#SP1 ...】`のような表記)。放送回番号(`9`のような数字)だけだとシリーズが変わると1話から
数え直すため種別全体では一意にならず、番号だけをseriesにすると別シリーズの同じ番号の回が
同じ見た目・同じ絞り込み対象になってしまう。そのためseriesはタイトルまで含めた文字列にして
種別全体で一意にし、ピンに表示する短い番号は`settings.json`の`series`側の`label`に分離してある。

前後編にまたがっていて前編・後編のどちらで登場したか分からないスポットは、
`【#17-18 ...】`のような合体表記ではなく**前編側の1回(`【#17 ...】`)に寄せる**
(かつて合体表記と単独表記が混在していたため統一した。#17-18・#21-22・#32-33・#38-39の
4件が該当)。`categories`列は`第<N>シリーズ`(1〜5)でシリーズを表す。

`settings.json`の`series`は全340回(5シリーズ合計)を放送順に列挙した機械生成(見た目は
全話共通、ピンには`label`の番号のみ表示)。この340回にはスポット行を持たない回も6回含まれる
(他の回のスポットから「【#…】でも訪れている」と参照されるだけの回。第3シリーズ
【#16 新宿誕生編(前編)】、第5シリーズ【#10 東京・青山通り…】・【#28 初詣スポット 川崎大師…】と、
重複統合でスポット行が他の回に寄せられた3回)。

**具体的なスポット名・説明文・各回との対応関係は未検証(要確認)。** シリーズごとに別々の
調査(別セッション)で作成したものを1ファイルに統合したため、同じ場所を複数シリーズ・
複数放送回にわたって再訪しているケースがある(例: 東京大学赤門は第1・第2・第5シリーズで
計3回登場)。travel-log側の取り込みが`name`+`lat`+`lng`の完全一致で重複除外するため、
CSV側でも先に訪れた回の行だけを残し、あとの回に訪れたことは残した行の`description`末尾に
追記する形で統合済み(重複行として残してはいない)。`key`列はスポット名(名前重複時のみ
`名前_2`の連番サフィックス)で全406件に付与。

## routes.csv

**巡回順が公表情報から裏取りできる回だけ**に絞ってある。かつては全56ルートを
「spots.csvの回ごとの行順をそのまま`seq`にする」機械生成で持っていたが、行順は巡回順の
根拠になっておらず(同一敷地内を結ぶ矢印すら含んでいた)、「巡った順」を騙る誤情報になる
ため廃止した。残した3ルートと、その順序の根拠:

- `伊勢神宮への旅(第5シリーズ#1〜#5)`: 5夜連続で桑名→四日市→鈴鹿→津→松阪→明和→伊勢と
  伊勢街道を南下する旅企画。夜ごとの訪問地(市町村)の並びがjawikiの放送日程節に載っており、
  回をまたいだ進行方向が確定する。回内の並びも街道の南下順に合わせてある
  (松阪市内の2件だけは前後関係が不明のため、街道の進行方向に沿う順に置いただけ)
- `富士山登山(第4シリーズ#19〜#21)`: jawikiの訪問地欄が「富士宮口五合目〜六合目」→
  「六合目〜宝永火口」→「九合五勺〜山頂〜剣ヶ峰」と登山の進行そのものを記載しており、
  回をまたいだ順序が確定する
- `大山詣り(第5シリーズ#12〜#13)`: 前編が中腹の下社、後編が「山頂へ」で本社。登拝順が確定する

上記以外の回は、立ち寄りスポットが1件しか採録されていないか、回内の順序を裏取りできないため
ルートを持たない(`spot_key`から参照されないスポットが大半になるが、`key`列自体は
再アップロード時の同一判定に使うため全件に付けたままにしている)。

## ライセンス

座標のみosm_japan(OSMのローカルミラー)で1件ずつ裏取りしているが、説明文・立ち寄り順は
一般知識からの作成。Overpass APIでの一括抽出(データベースからの実質的な取り出し)ではなく
既知の地点を個別に参照した程度のため、ODbLの表示義務は適用されないと考えている
(まとまった量の再配布にあたるかどうかの境界事例ではあるので、大量に追加抽出する場合は
改めて要検討)。
